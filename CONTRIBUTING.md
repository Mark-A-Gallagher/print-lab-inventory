# Contributing

Thank you for your interest in contributing to the 3D Print Lab Inventory System!

This project is primarily developed as a personal software engineering project, but suggestions, bug reports, and contributions are welcome.

## How to Contribute

### Reporting Bugs

If you encounter a bug, please open a GitHub Issue and include:

- A clear description of the problem.
- Steps to reproduce the issue.
- What you expected to happen.
- What actually happened.
- Any relevant error messages or screenshots.

### Suggesting Improvements

Feature requests and improvements are welcome. When suggesting an enhancement, please explain:

- What functionality you would like to see.
- Why it would be useful.
- How it could improve the existing application.

### Submitting Changes

If you would like to contribute code:

1. Fork the repository.
2. Create a new branch for your changes.
3. Make your changes and test them.
4. Commit your changes with a descriptive commit message.
5. Push your branch to your fork.
6. Open a Pull Request describing your changes.

## Development Guidelines

To maintain consistency throughout the project:

- Follow the existing project structure and coding conventions.
- Keep changes focused and avoid unrelated modifications.
- Validate inputs and handle errors appropriately.
- Preserve existing inventory and reservation business rules.
- Ensure inventory calculations and event history remain consistent.
- Test changes before submitting a Pull Request.
- Update documentation when introducing significant changes.

## Project Design

Before making significant architectural or functional changes, review [DESIGN.md](DESIGN.md).

This document outlines the project's architecture, database structure, business rules, event-sourced inventory system, and design decisions.

Changes should remain consistent with the established design unless an intentional improvement is being proposed.

## Code of Conduct

Please be respectful and constructive when interacting with the project and other contributors.
